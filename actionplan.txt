ISSUE IDENTIFIED: Customers not showing in customers page when they send messages

### Root Cause Analysis:
- Webhook receives messages and processes them correctly
- Messages get stored in chat history
- BUT customer records are NOT being created for people who send messages
- Only people who get enrolled in sequences get customer records created
- This means anyone who sends a message but doesn't match sequence criteria becomes invisible in customers page

### Solution Implemented:
1. **Added new method to CustomersService**: `createCustomerFromMessage()` 
   - Creates customer record for ANY person who sends a message
   - Uses phone as fallback name if pushName not available
   - Sets default type as 'lead' with empty enrolled sequences

2. **Modified webhook.js to create customer for every message**:
   - Added customer creation logic right after chat message storage
   - Ensures ALL message senders appear in customers page regardless of sequence matching
   - Existing customer update logic for enrollments preserved

3. **Enhanced enrollment customer handling**:
   - Added call to `createCustomerFromEnrollment()` when someone gets enrolled
   - This updates existing customer records with sequence enrollment data

### Expected Outcome:
- ALL people who send messages now appear in customers page
- Customer records created immediately upon first message
- Enrollment still updates customer records properly
- No behavioral changes to existing functionality

**Files Modified:**
- backend/services/customers.service.js (added createCustomerFromMessage method)
- backend/routes/webhook.js (added customer creation for all messages)

## Technical Details:
**Problem Example**: 
- Ignore keyword: "hi"
- Message: "how to make payment to this software"  
- "how" contains "hi" → false positive block

**Solution**:
- **Before**: `messageLower.includes(keyword.toLowerCase())` - matches substrings
- **After**: `new RegExp('\\b' + keyword + '\\b', 'i').test(message)` - matches whole words only

**Fixed Locations**:
1. Frontend: `ai-agents.controller.js` - test agent ignore keyword validation
2. Backend: `ai.service.js` - shouldRespond function ignore keyword checking

- "hi" ignore keyword + "this software" message → allowed ✅

### Iteration 10: AI Agent API Migration
**Status**: In Progress
**Objective**: Change AI agent message sending from Meta Cloud API to wa.robomate.in API
**Problem Identified**: AI agents using Facebook Graph API instead of wa.robomate.in API
**Root Cause**: `sendAIResponse` function in webhook.js using wrong API endpoint and payload format

### Changes Made:
**API Endpoint Migration**:
- **FROM**: `https://graph.facebook.com/v17.0/${instanceId}/messages` (Meta Cloud API)
- **TO**: `https://wa.robomate.in/api/send` (wa.robomate.in API)

**Payload Format Change**:
- **FROM**: Meta Cloud API format:
  ```js
  {
    messaging_product: "whatsapp",
    to: phone,
    type: "text", 
    text: { body: message }
  }
  ```
- **TO**: wa.robomate.in API format:
  ```js
  {
    number: phone,
    type: 'text',
    message: message,
    instance_id: instanceId,
    access_token: accessToken
  }
  ```

**Request Method Change**:
- **FROM**: JSON POST with Authorization Bearer token
- **TO**: Form-encoded POST with URL-encoded payload

**Response Handling Update**:
- Added proper wa.robomate.in API response handling
- Check for `status: 'success'` or `success: true`
- Handle `status: 'error'` responses with detailed logging
- Added timeout handling (30 seconds)
